# V1 迁移诊断

用户于2026-09-28授权继续定位无明显元训练收益的原因。诊断不修改 V1 训练、划分或历史结果。

- `configs/diagnostics.yaml` 固定诊断范围，结果写入 `outputs/diagnostics_v1/`。
- `scripts.audit_transfer` 读取全部130组已有权重，汇总适应曲线、support/query误差、表示尺度和有效秩。
- 固定目标第0步的同一 Encoder/Mapper，仅替换源初始/最终 G，计算预测位移和位置等权误差。不得据目标结果选择新超参数。
- `scripts.audit_gradients` 对首批 T1_B0F1_e0、T2_B2F3_e0 重放100轮，复用 SourceClient/meta_round 及保存的行号。
- 梯度对齐比例为 `||mean(g_k)|| / mean(||g_k||)`；相对步长为 `||实际参数变化|| / ||更新前参数||`。只记录，不修改梯度。
- 重放只验证现有更新强度与源任务贡献，不代表完整1000轮结果，也不作为源域开发任务的替代。
- 目标 AE 在相同30条 support上重放；核对 Encoder 与保存的第0步权重一致，再比较重建与恒零/逐AP均值预测。Query不参与AE。
- 源AE日志末次MSE来自最后一个batch；全P_C常数基线只是参考，不能与不同batch直接据此判定优劣。
- 有效秩使用中心化 latent 奇异值能量的参与率。低有效秩只表示表征变化集中，不自动判为塌缩。
- 下一阶段是否建立优化尺度核验版取决于此诊断；新优化参数只能使用源域内部留出的开发任务，不能用已观察目标query调参。

## AE 饱和跟进

两份目标AE重建误差与恒零基线一致，故新增 `scripts.audit_autoencoder` 核验输出最大值和小于1e-6的比例。
学习率对照只使用 T2_B2F3_e0 的8个源楼层，固定200步、相同初值和batch，比较0.0095/0.001/0.0001。
从源P_C训练，源P_Q仅评价重建；不使用目标域选择学习率，不改变定位阶段encoder学习率，也不更新V1默认配置。
这是AE数值诊断，不等同元学习改进已经验证。目标端只重放原始0.0095设置。

原0.0095输出全部为零，0.001大部分接近零，0.0001在200步避免饱和但重建仍差于常数基线。
因此固定0.0001追加200/500/1000/2000步的源楼层重建曲线。前200个batch与V1一致，后续由同一采样器扩展并保存行号。
不扫描其他学习率，不读取B2进行设置选择；该跟进不是定位实验，不声称解决泛化问题。

## 源域内部定位开发对照

0.0001/2000步在8个源楼层的P_Q上均优于常数重建后，运行 `scripts.source_dev_ae`。
从B0/B1的8楼层中留出B1F3，余7楼层训练1000轮；B1F3使用既有e0 support/query适应500步。
比较原AE(.0095/200)和修正AE(.0001/2000)，其余网络、元训练、定位学习率及数据完全相同。
仅RI/MI两种初始化，不重跑WKNN/MLP。此楼层属于开发数据，且AE诊断曾使用其RSSI，因此不把它当作独立测试。
B2完全不进入这次开发对照。结果保存 `outputs/source_dev_ae/`，不覆盖正式V1。

## 外层尺度有界核验

修正AE改善了开发任务早期误差，但共享G的相对变化仍只有约0.1%。因此在完全相同源/开发划分上，
固定修正AE，额外比较外层学习率.01与.1；.001参考复用repaired_ae结果。
不扩大搜索，仍1000轮/500适应步；仅改变外层lr。配置 `configs/source_dev_scale.yaml`。
两个设置即使改善也只算开发结果，不能直接视为B2泛化收益；不自动重跑正式130组。
